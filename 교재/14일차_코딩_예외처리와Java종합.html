1. 쉬운 설명 · 문제가 생겼을 때 갈 길을 정하기

예외는 실행 중 정상 작업을 계속하기 어려운 상황입니다. 숫자 대신 글자가 들어오거나, 없는 배열 칸을 읽거나, 정수를 0으로 나누는 경우가 있습니다. 예외를 잡으면 정해 둔 대체 작업을 하고 다음 흐름을 이어갈 수 있습니다.

문법쉽게 말하면기억할 점
try우선 이 일을 해 보기위에서 아래로 실행
catch문제가 생기면 이쪽에서 처리실제 예외와 맞는 catch 한 곳
finally이 구간을 떠나기 전에 마무리정상·예외·return에도 실행
throw지금 예외를 발생시키기실행문
throws이 메서드가 예외를 밖으로 보낼 수 있다고 선언메서드 선언부. 처리 기능은 없음

예제 E01 · 예외가 없으면

public class Main {

    public static void main(String[] args) {
        int divisor = 4;
        try {
            System.out.print("start ");
            System.out.print(28 / divisor + " ");
        } catch (ArithmeticException e) {
            System.out.print("error ");
        } finally {
            System.out.print("finish ");
        }
        System.out.println("next");
    }
}
start 7 finish next

28/4는 정상입니다. catch는 지나치고 finally를 실행한 뒤 바깥으로 갑니다.

예제 E02 · 중간에서 예외가 나면

public class Main {

    public static void main(String[] args) {
        int divisor = 0;
        try {
            System.out.print("start ");
            System.out.print(28 / divisor + " ");
            System.out.print("success ");
        } catch (ArithmeticException e) {
            System.out.print("error ");
        } finally {
            System.out.print("finish ");
        }
        System.out.println("next");
    }
}
start error finish next

나눗셈 줄에서 흐름이 꺾입니다. success로 복귀하지 않습니다. catch → finally → next로 진행합니다.

정상: try 끝까지 → catch 건너뜀 → finally → 다음 줄 예외: try 중단 → 맞는 catch → finally → 다음 줄 미처리 예외: try 중단 → finally → 바깥 처리기 찾기

예외가 발생했다는 이유만으로 앞서 바뀐 변수까지 원상복구되지는 않습니다. 또한 catch 뒤에 있는 코드를 계속 실행하려면 해당 예외가 처리되어야 합니다.

먼저 알아둘 대표 예외

예외발생 예직관
ArithmeticException정수 12 / zero, zero가 0나눌 수 없음
ArrayIndexOutOfBoundsException길이3 배열의 a[3]없는 칸
NullPointerExceptionnull인 s의 s.length()객체가 없음
NumberFormatExceptionInteger.parseInt("hi")숫자로 바꿀 수 없음
IllegalArgumentException허용 범위 밖 입력을 직접 거절인수가 조건에 맞지 않음
ClassCastException실제 부모 객체를 자식 객체로 형변환실제 객체 종류가 맞지 않음

예제 E03 · 서로 다른 실패를 구분하기

public class Main {

    public static void main(String[] args) {
        for (String raw : new String[]{"6", "?", "0"}) {
            try {
                int n = Integer.parseInt(raw);
                System.out.print(24 / n + " ");
            } catch (NumberFormatException e) {
                System.out.print("문자오류 ");
            } catch (ArithmeticException e) {
                System.out.print("나눗셈오류 ");
            }
        }
    }
}
4 문자오류 나눗셈오류

"?"는 변환 단계에서 실패합니다. "0"은 정수 변환에는 성공하고 나눗셈에서 실패합니다. 한 try에서 catch를 두 개 모두 실행하는 것은 아닙니다.

손으로 푸는 순서 · ① 현재 값 적기 ② 실제 객체 확인 ③ 예외 발생 줄 표시 ④ 같은 try의 남은 줄 지우기 ⑤ 맞는 catch 한 곳 ⑥ finally ⑦ 반환값과 출력 순서를 따로 적기.

2. 응용 설명 · 반복과 메서드에 예외 섞기

try를 어디에 두느냐가 계속 처리할 범위를 정한다

// 원소별 처리: 하나가 실패해도 다음 원소로 간다.
for (int n : data) {
    try { /* 현재 원소 처리 */ }
    catch (ArithmeticException e) { /* 현재 원소 실패 처리 */ }
}

// 전체 처리: 중간 실패 시 반복문을 벗어난다.
try {
    for (int n : data) { /* 원소 처리 */ }
} catch (ArithmeticException e) { /* 전체 작업 실패 처리 */ }

성적 100명 중 한 명의 잘못된 입력만 제외하려면 원소마다 처리합니다. 전체 작업이 함께 성공해야 하는 상황은 별도 설계가 필요합니다. try를 바깥에 둔다고 이미 바뀐 데이터가 자동으로 되돌아가지는 않습니다. C13·C14를 나란히 추적해 보세요.

예제 E04 · throw는 발생, throws는 선언

public class Main {
    static int checkedScore(int score) throws Exception {
        if (score < 0 || score > 100) throw new Exception("score");
        return score;
    }
    public static void main(String[] args) {
        for (int n : new int[]{40, -2, 80}) {
            try {
                System.out.print(checkedScore(n) + " ");
            } catch (Exception e) {
                System.out.print("범위오류 ");
            }
        }
    }
}
40 범위오류 80

메서드 안 throw가 잘못된 점수를 거절합니다. throws Exception은 호출자에게 처리 책임을 알립니다. 이 예제에서는 main의 catch가 처리합니다.

종류기준호출자에게 요구되는 것
checked 예외Exception 계열 중 RuntimeException 계열을 제외한 예외catch로 처리하거나 throws로 전달 선언
unchecked 예외RuntimeException 계열. 예: 숫자 변환·배열·정수 나눗셈 오류catch나 throws가 컴파일 시 필수는 아님. 필요에 따라 처리

모든 오류가 catch(Exception)으로 잡히는 것은 아닙니다. Error 계열은 별개입니다. 오늘 연습에서는 보통의 예외 흐름에 집중합니다.

catch는 구체적인 자식 타입부터

try {
    // 변환·계산
} catch (NumberFormatException e) {
    // 숫자 변환 실패만 처리
} catch (IllegalArgumentException e) {
    // NumberFormatException도 포함하는 더 넓은 범위
} catch (Exception e) {
    // 나머지 Exception 계열
}

상속 관계에서 큰 범위가 앞에 있으면 뒤의 작은 범위는 도달할 수 없어 컴파일 오류입니다. 이미 실행한 catch 안에서 새로 난 예외는 옆 catch가 받지 않습니다. 바깥 try가 필요합니다.

3. 심화 설명 · 반환값·객체·공유값을 함께 추적하기

예제 E05 · return 값을 준비한 뒤 finally 실행

public class Main {
    static int calc() {
        int x = 3;
        try {
            x += 4;
            return x;
        } finally {
            x += 5;
            System.out.print(x + " ");
        }
    }
    public static void main(String[] args) {
        System.out.println(calc());
    }
}
12 7

반환 준비 값은 7입니다. finally가 지역변수 x를 12로 바꾸어 먼저 출력합니다. 호출자에게 돌아가는 기본형 값은 준비해 둔 7입니다.

객체 참조를 반환할 때는 같은 객체의 필드가 finally에서 바뀌면 그 변경이 보입니다(C26). finally 자체가 return하거나 예외를 던지면 앞의 반환·예외를 덮을 수 있습니다(C27·C28). 마무리 코드에는 흐름을 덮는 return을 쓰지 않는 편이 좋습니다.

finally의 범위 · 보통의 메서드 실행에서는 정상·예외·return·break·continue 때 모두 거칩니다. JVM 강제 종료, 프로세스 중단, 전원 종료처럼 실행 자체가 끊기면 보장할 수 없습니다.

예제 E06 · 메서드는 실제 객체, static은 공유

class Meter {
    static int calls;
    int base = 3;
    int read(int n) { calls++; return 9 / n; }
}
class FastMeter extends Meter {
    int base = 18;
    @Override int read(int n) { calls++; return base / n; }
}
public class Main {

    public static void main(String[] args) {
        Meter a = new FastMeter();
        Meter b = new FastMeter();
        int total = 0;
        try {
            total += a.read(3);
            total += b.read(0);
            total += 100;
        } catch (ArithmeticException e) {
            total += a.base;
        } finally {
            System.out.print(Meter.calls + " ");
        }
        System.out.println(total);
    }
}
2 9

a.read(3)은 실제 FastMeter의 18/3=6입니다. b.read(0)은 calls를 증가시킨 뒤 실패합니다. catch의 a.base는 참조 타입 Meter 기준인 3입니다. calls=2, total=9입니다.

추적 대상확인할 것
필드 p.x참조 변수에 선언한 타입
오버라이딩 메서드 p.calc()실제로 new한 객체 타입
static 필드같은 클래스의 여러 객체가 공유하는 한 값
예외 발생 전 변경이미 완료했다면 그대로 남음
예외 발생 줄의 대입오른쪽 계산이 끝나지 않으면 대입 완료 안 됨

4. 연습 36문제 · 먼저 답을 쓰고 실행하기

C09·C35는 컴파일 가능 여부와 수정 방법을 쓰세요. 나머지는 출력 결과를 줄바꿈까지 예측하고, 예외가 발생한 줄·건너뛴 줄·변수 변화를 기록하세요. 출력 끝의 공백은 채점 핵심에서 제외합니다.

기본 C01~C12 · 실행 흐름

연습 C01

정상 실행이면 catch는 건너뛴다

public class Main {

    public static void main(String[] args) {
        try {
            System.out.print("A");
            System.out.print(18 / 3);
        } catch (ArithmeticException e) {
            System.out.print("B");
        } finally {
            System.out.print("C");
        }
        System.out.print("D");
    }
}

18 / 3은 정상입니다. catch는 건너뛰고 finally의 C와 바깥 D를 출력합니다.

public class Main {

제작 P01

성적 문자열 정제기

요구사항 · 입력 {"75", "bad", "110", "90", "-3"}에서 0~100인 정수만 합산하세요. 유효 개수, 합계, 정수 평균을 출력하세요. 숫자 변환 실패와 범위 오류는 모두 오류 개수에 포함합니다.

설계 힌트 · 원소마다 try → 정수 변환 → 범위 검사 → 성공 집계. 실패한 원소는 합계와 유효 개수를 바꾸지 않습니다.

정답과 풀이
public class Main {

    public static void main(String[] args) {
        String[] input = {"75", "bad", "110", "90", "-3"};
        int sum = 0, valid = 0, errors = 0;
        for (String raw : input) {
            try {
                int n = Integer.parseInt(raw);
                if (n < 0 || n > 100) throw new IllegalArgumentException();
                sum += n;
                valid++;
            } catch (IllegalArgumentException e) {
                errors++;
            }
        }
        System.out.println(valid + " " + sum + " " + (valid == 0 ? 0 : sum / valid));
        System.out.println("errors=" + errors);
    }
}

errors=3

NumberFormatException은 IllegalArgumentException의 자식이므로 같은 catch로 처리할 수 있습니다. 유효 값이 하나도 없는 경우 0으로 나누지 않게 합니다. 추가 검증: {"x","101"}이면 0 0 0 / errors=2입니다.

class Account {
    static int attempts;
    int balance, success;
    Account(int n) { balance = n; }
    void withdraw(int n) {
        attempts++;
        if (n <= 0 || n > balance) throw new IllegalArgumentException();
        balance -= n;
        success++;
    }
}
public class Main {

    public static void main(String[] args) {
        Account a = new Account(500);
        for (int n : new int[]{120, -5, 600, 80}) {
            try { a.withdraw(n); }
            catch (IllegalArgumentException e) { System.out.print("X "); }
        }
        System.out.println("| " + a.balance + " " + Account.attempts + " " + a.success);
    }
}
X X | 300 4 2

정상 출금은 120과 80입니다. 실패 두 건은 잔액에 영향을 주지 않습니다. 추가 검증: 새 계좌에서 잔액과 같은 금액은 출금할 수 있습니다.

제작 P04

상속을 사용한 거리 요금 계산

요구사항 · Fare 참조로 StudentFare 객체를 사용하세요. 거리 문자열 {"6", "-1", "?", "3"}을 처리하여 성공 요금 합계를 출력하세요. 일반 요금은 거리×100, 학생 요금은 거리×60이며 음수 거리는 거절합니다.

설계 힌트 · 부모 메서드에 공통 거리 검사, 자식에 요금 계산을 둡니다. 원소마다 예외를 처리하고 다음 입력을 계속 읽습니다.

정답과 풀이
class Fare {
    void check(int km) { if (km < 0) throw new IllegalArgumentException(); }
    int price(int km) { check(km); return km * 100; }
}
class StudentFare extends Fare {
    @Override int price(int km) { check(km); return km * 60; }
}
public class Main {

    public static void main(String[] args) {
        Fare fare = new StudentFare();
        int total = 0, errors = 0;
        for (String raw : new String[]{"6", "-1", "?", "3"}) {
            try { total += fare.price(Integer.parseInt(raw)); }
            catch (IllegalArgumentException e) { errors++; }
        }
        System.out.println(total + " " + errors);
    }
}
540 2

호출은 실제 StudentFare 객체 기준입니다. 6×60 + 3×60 = 540입니다. 추가 검증: 거리0은 허용하며 요금0입니다.

제작 P05

인터페이스 작업 처리기와 종료 기록

요구사항 · Job 인터페이스를 구현한 DivideJob으로 {4, 0, 2}를 처리하세요. 각 작업은 24/n을 반환합니다. 실패는 합계에 더하지 않고, finally에서 모든 처리 횟수를 기록하세요.

설계 힌트 · 인터페이스 배열이나 공통 참조로 호출할 수 있게 만듭니다. 정상 결과 합계와 시도 횟수를 따로 둡니다.

정답과 풀이
interface Job { int run(int n); }
class DivideJob implements Job {
    public int run(int n) { return 24 / n; }
}
public class Main {

    public static void main(String[] args) {
        Job job = new DivideJob();
        int total = 0, finished = 0;
        for (int n : new int[]{4, 0, 2}) {
            try { total += job.run(n); }
            catch (ArithmeticException e) { System.out.print("E "); }
            finally { finished++; }
        }
        System.out.println("| " + total + " " + finished);
    }
}
E | 18 3

24/4=6, 실패, 24/2=12입니다. finally는 세 작업에서 모두 실행됩니다. 추가 검증: {0,0}이면 합계0, 처리2입니다.

제작 P06

최대 세 번 재시도하기

요구사항 · read()가 처음 두 호출에서는 IllegalStateException을 던지고 세 번째에는 42를 반환하도록 만드세요. 최대 3번 시도하고 성공하면 즉시 반복을 끝내세요. 매 시도마다 finally에서 F를 출력하세요.

설계 힌트 · 반복 번호 → try에서 호출 → 성공이면 break → 실패면 다음 반복. break 직전에도 finally가 실행됩니다.

정답과 풀이
public class Main {
    static int calls;
    static int read() {
        calls++;
        if (calls < 3) throw new IllegalStateException();
        return 42;
    }
    public static void main(String[] args) {
        boolean ok = false;
        for (int i = 1; i <= 3; i++) {
            try {
                int value = read();
                System.out.print(value + " ");
                ok = true;
                break;
            } catch (IllegalStateException e) {
                System.out.print("retry ");
            } finally {
                System.out.print("F ");
            }
        }
        System.out.println("| " + ok + " " + calls);
    }
}
retry F retry F 42 F | true 3

실패2회 후 성공1회입니다. 무한 반복 대신 상한을 둡니다. 추가 검증: 최대 시도를2로 바꾸면 retry F retry F | false 2입니다.

제작 P07

행 데이터 오류 분류기

요구사항 · 문자열 {"A:12", "B:x", "broken", "C:8", "D:-2"}를 이름:점수로 분리하세요. 형식 오류, 숫자 오류, 범위 오류를 따로 세고 정상 점수 합계를 출력하세요. 점수는 0~100만 허용합니다.

설계 힌트 · split(":", -1) 결과 길이를 먼저 확인합니다. 그 뒤 숫자 변환을 하고 범위를 검사합니다. catch는 자식 NumberFormatException부터 둡니다.

정답과 풀이
public class Main {

    public static void main(String[] args) {
        int sum = 0, format = 0, number = 0, range = 0;
        for (String row : new String[]{"A:12", "B:x", "broken", "C:8", "D:-2"}) {
            String[] cells = row.split(":", -1);
            if (cells.length != 2 || cells[0].isEmpty() || cells[1].isEmpty()) {
                format++;
                continue;
            }
            try {
                int n = Integer.parseInt(cells[1]);
                if (n < 0 || n > 100) throw new IllegalArgumentException();
                sum += n;
            } catch (NumberFormatException e) {
                number++;
            } catch (IllegalArgumentException e) {
                range++;
            }
        }
        System.out.println(sum + " " + format + " " + number + " " + range);
    }
}
20 1 1 1

A와 C가 정상입니다. broken은 형식, B는 숫자 변환, D는 범위 오류입니다. 추가 검증: "Z:"는 형식 오류로 셉니다.

제작 P08

선택 심화 · FIFO 페이지 교체를 코드로 구현

요구사항 · 프레임 3개를 -1로 비워 두고 페이지 참조 {2, 5, 2, 7, 8, 5}를 처리하세요. 이미 있으면 적중, 없으면 next 위치에 넣고 next를 순환시킵니다. 페이지 부재 횟수와 마지막 프레임을 출력하세요.

설계 힌트 · 각 페이지를 프레임 전체에서 검색 → 적중이면 유지 → 부재면 frames[next] 교체 → next=(next+1)%3. 적중 시 next를 바꾸면 FIFO가 아닙니다.

정답과 풀이
public class Main {

    public static void main(String[] args) {
        int[] frames = {-1, -1, -1};
        int next = 0, faults = 0;
        for (int page : new int[]{2, 5, 2, 7, 8, 5}) {
            boolean hit = false;
            for (int value : frames) {
                if (value == page) hit = true;
            }
            if (!hit) {
                frames[next] = page;
                next = (next + 1) % frames.length;
                faults++;
            }
        }
        System.out.println("faults=" + faults);
        for (int value : frames) System.out.print(value + " ");
    }
}
faults=4
8 5 7

2·5·7 최초 적재3회, 8 적재1회입니다. 마지막5는 적중입니다. 이론의 FIFO와 연결하는 선택 심화 과제입니다. 추가 검증: {1,1,1}은 부재1회입니다.
