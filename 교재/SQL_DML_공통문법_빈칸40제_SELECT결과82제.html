01. 사용법

  1. 별도의 실습용 DB에 연결한 뒤 준비 SQL을 한 번 실행합니다. SQL 편집기는 pgAdmin·DBeaver 등 어느 것이든 괜찮습니다.
  2. SELECT: 쿼리를 읽고 결과표를 먼저 씁니다. 그다음 실제 DB 결과와 정답을 확인합니다.
  3. INSERT·UPDATE·DELETE: 실제 세 표를 직접 수정합니다. 매 문제마다 START TRANSACTION; → 완성한 SQL → 확인 SQL → ROLLBACK; 순서로 같은 연결에서 실행합니다. 마지막 ROLLBACK이 그 문제의 변경을 되돌립니다.
  4. 브라우저의 빈칸 채점은 대표 답안의 표기만 비교합니다. SELECT 답안 칸은 직접 비교하는 연습장입니다. 이 HTML은 DB에 연결하지 않습니다.

SQL 예약어는 대소문자를 구분하지 않지만 문자열 값은 작은따옴표로 씁니다. 조회 수와 좋아요 수는 학습용 고정 정수입니다. 소수 끝의 0은 생략하며, 순환소수는 소수 여섯째 자리까지 반올림해 ≈로 표시합니다. NULL은 화면의 빈 칸과 구분해서 적으세요.

인쇄물의 모든 문제는 03 기준 데이터를 공통으로 사용합니다. DML은 매 문제 초기 상태로 되돌린다고 가정합니다.

04. 짧은 문법 · 한 기능, 한 예제

작성: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
결과 추적: FROM·JOIN → WHERE → GROUP BY·집계 → HAVING → SELECT → DISTINCT → ORDER BY → OFFSET·FETCH

결과 추적을 위한 학습용 순서입니다. DB 엔진의 실제 물리 실행 순서를 뜻하지 않습니다. GROUP BY를 사용하면 SELECT의 일반 열은 그룹 기준에 넣고, 나머지는 집계합니다. SELECT 별칭은 ORDER BY에서 쓰되 WHERE·HAVING에서는 원래 식을 쓰는 방식으로 통일합니다.

게시글 입력

열과 값의 개수·순서를 맞춥니다.

INSERT INTO tbl_board (post_id, title, user_id) VALUES (9, 'New Post', 10);
관련 문제 D001

조회 결과로 댓글 입력

VALUES 대신 SELECT를 붙입니다.

INSERT INTO tbl_comment (comment_id, post_id, user_id, content) SELECT post_id + 100, post_id, 40, 'Read'
FROM tbl_board
WHERE status = 'PUBLIC';
관련 문제 D008

제목·상태 수정

여러 열의 대입은 쉼표, 대상 조건은 WHERE입니다.

UPDATE tbl_board SET title = 'SQL Quiz v2', status = 'PUBLIC'
WHERE post_id = 3;
관련 문제 D016

게시글 삭제

행을 삭제합니다. WHERE가 없으면 전체 행입니다.

DELETE
FROM tbl_board
WHERE post_id = 2;
관련 문제 D029

중복·정렬

DISTINCT는 선택한 열 조합 전체의 중복을 제거합니다. 

SELECT DISTINCT view_count
FROM tbl_board
WHERE view_count IS NOT NULL
ORDER BY view_count;
관련 문제 S003

조회 수 조건

BETWEEN은 양 끝 값을 포함합니다.

SELECT post_id
FROM tbl_board
WHERE view_count BETWEEN 2000 AND 3000
ORDER BY post_id;
관련 문제 S013

미집계 값 NULL

좋아요 미집계 NULL과 좋아요 0을 구분합니다.

SELECT post_id
FROM tbl_board
WHERE like_count IS NULL
ORDER BY post_id;
관련 문제 S021

조건별 인기 등급

CASE는 값 하나를 만드는 식입니다.

SELECT post_id, CASE WHEN view_count >= 3000 THEN 'HOT' WHEN view_count >= 2000 THEN 'MID' ELSE 'LOW' END AS grade
FROM tbl_board
WHERE post_id IN (1, 2, 5, 7)
ORDER BY post_id;
관련 문제 S028

게시글 집계

COUNT(*)는 글 수, COUNT(열)은 알려진 값의 수입니다. 

SELECT COUNT(*) AS post_n, COUNT(view_count) AS known_views, COUNT(like_count) AS known_likes
FROM tbl_board;
관련 문제 S041

유저별 글 수

WHERE는 묶기 전, HAVING은 묶은 후입니다.

SELECT user_id, COUNT(*) AS post_n
FROM tbl_board
WHERE user_id IS NOT NULL
GROUP BY user_id
HAVING COUNT(*) >= 2
ORDER BY user_id;
관련 문제 S047

글·작성자 조인

두 표의 유저 번호가 같은 행을 연결합니다.

SELECT b.post_id, u.nickname
FROM tbl_board b
INNER JOIN tbl_user u ON b.user_id = u.user_id
ORDER BY b.post_id;
관련 문제 S051

댓글 없는 글도 보존

LEFT는 왼쪽 글을 보존하고 미매칭 댓글 열을 NULL로 채웁니다. 

SELECT b.post_id, c.comment_id
FROM tbl_board b
LEFT OUTER JOIN tbl_comment c ON b.post_id = c.post_id
WHERE b.post_id IN (1, 4)
ORDER BY b.post_id, c.comment_id;
관련 문제 S053

최고 조회 수 글

괄호 속 SELECT의 값을 바깥에서 사용합니다.

SELECT post_id, view_count
FROM tbl_board
WHERE view_count = (SELECT MAX(view_count) FROM tbl_board)
ORDER BY post_id;
관련 문제 S063

댓글 유무

EXISTS는 행의 존재만 검사합니다. SELECT 1은 관용 표현입니다. 

SELECT b.post_id
FROM tbl_board b
WHERE EXISTS (SELECT 1 FROM tbl_comment c WHERE c.post_id = b.post_id)
ORDER BY b.post_id;
관련 문제 S066

ANY·ALL

ANY는 하나라도, ALL은 모두 만족해야 합니다. SOME은 ANY와 같습니다. 

SELECT post_id
FROM tbl_board
WHERE view_count > ALL (SELECT view_count FROM tbl_board WHERE user_id = 10)
ORDER BY post_id;
관련 문제 S069

활동 유저 집합

UNION 합집합, INTERSECT 교집합, EXCEPT 차집합. ALL은 중복 개수를 반영합니다. 

SELECT user_id
FROM tbl_board
EXCEPT SELECT user_id
FROM tbl_comment
ORDER BY user_id;
관련 문제 S080

작성자별 합계 CTE

WITH로 한 문장 안에서 사용할 조회 이름을 붙입니다. 

WITH totals AS (
    SELECT user_id, SUM(view_count) AS total_views
    FROM tbl_board WHERE user_id IS NOT NULL GROUP BY user_id
)
SELECT user_id, total_views FROM totals
WHERE total_views >= 5000 ORDER BY user_id;
관련 문제 S084
조인을 풀 때 · INNER는 매칭만, LEFT·RIGHT는 지정한 쪽을 보존, CROSS는 모든 조합입니다. SELF JOIN은 같은 표에 별칭을 둘 붙이는 방법입니다. 등호 대신 범위 조건을 ON에 쓰는 비동등 조인도 같은 원리로 계산합니다.

NULL의 3값 논리 · 이 표만 기억하세요

A B A AND B A OR B
TRUE UNKNOWN UNKNOWN TRUE
FALSE UNKNOWN FALSE UNKNOWN
UNKNOWN UNKNOWN UNKNOWN UNKNOWN

NOT UNKNOWN도 UNKNOWN입니다. WHERE·HAVING·JOIN ON은 TRUE인 경우만 통과시킵니다. GROUP BY·DISTINCT·집합 연산의 중복 판정에서는 NULL끼리를 한 묶음으로 취급합니다.

변경 문제는 빈칸, 조회 문제는 결과표를 채우세요. SELECT는 열 이름과 행 순서를 함께 적습니다. 각 문제의 “기준표”를 펼치면 필요한 원본 데이터를 바로 볼 수 있습니다.
