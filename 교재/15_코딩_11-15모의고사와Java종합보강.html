쉬운 설명 · 클래스는 설계도, 객체는 실제 물건

new 한 번에 실제 객체 하나가 생깁니다. 변수 이름이 두 개라고 객체도 두 개인 것은 아닙니다. 각 객체의 필드는 따로 있고 static 필드는 클래스의 여러 객체가 공유합니다. 생성자는 new할 때 처음 상태를 정합니다.

쉬운 예제 · 같은 객체를 가리키는 두 이름

class Cup { int amount; Cup(int n) { amount = n; } }
public class Main {

    public static void main(String[] args) {
        Cup a = new Cup(6);
        Cup b = a;
        b.amount += 2;
        System.out.println(a.amount + " " + b.amount);
    }
}
8 8

a와 b에서 같은 객체로 화살표를 그려 보세요. b로 바꾼 값도 a가 읽으면8입니다.

응용 설명 · 공통 타입으로 다른 동작 호출

상속은 공통 상태·동작을 물려받는 것입니다. 오버라이딩은 자식이 같은 메서드의 동작을 다시 정하는 것입니다. 부모 타입 변수로 불러도 재정의된 인스턴스 메서드는 실제 객체를 기준으로 실행합니다. 반면 필드와 static 메서드를 고를 때는 참조 타입을 봅니다.

응용 예제 · 필드와 메서드의 기준

class Tool { int power = 4; int result() { return power; } }
class FastTool extends Tool { int power = 9; @Override int result() { return power * 2; } }
public class Main {

    public static void main(String[] args) {
        Tool t = new FastTool();
        System.out.println(t.power + " " + t.result());
    }
}
4 18

t.power는 Tool의4, result는 실제 FastTool의 동작으로9×2=18입니다.

심화 설명 · 예외가 난 줄에서 정상 흐름은 꺾인다

try에서 예외가 나면 그 뒤의 같은 try는 건너뜁니다. 맞는 catch 한 곳을 실행하고 finally를 거쳐 다음으로 갑니다. 이미 바뀐 필드·static 값은 자동으로 복구되지 않습니다. return의 기본형 값은 finally 전에 준비되고, 객체 참조를 반환하면 같은 객체의 필드 변경은 보입니다.

심화 예제 · 실패 전후의 상태를 나눠 적기

class Meter {
    static int calls;
    int total;
    void add(int d) { calls++; total += 24 / d; }
}
public class Main {

    public static void main(String[] args) {
        Meter m = new Meter();
        for (int d : new int[]{2, 0, 4}) {
            try { m.add(d); }
            catch (ArithmeticException e) { System.out.print("E "); }
            finally { System.out.print(m.total + " "); }
        }
        System.out.println("| " + Meter.calls);
    }
}
12 E 12 18 | 3

첫 호출에서 total12입니다. 두 번째는 calls만 증가하고 나눗셈이 실패하므로 total은12입니다. 마지막에6을 더해18, 호출수는3입니다.

try가 반복문 안에 있으면 현재 원소의 실패를 잡고 다음 반복으로 갑니다. try가 반복문 전체를 감싸면 한 번의 예외가 반복문 전체를 벗어나게 합니다. finally는 일반적인 실행에서 return·break·continue 때도 거치지만 JVM 강제 종료 등에서는 보장되지 않습니다.

R01

새 객체와 원래 참조를 구별

class Item { int value; Item(int n) { value = n; } }
public class Main {

    public static void main(String[] args) {

        Item b = a;
        b = new Item(9);

        System.out.println(a.value + " " + b.value);

정답과 풀이
4 10

b가 새 객체를 가리키게 되면 a와 분리됩니다. a는4, b만10입니다.

R02

R16

R20

마지막 종합 재풀이

interface Rule { int apply(int n); }
abstract class Base implements Rule { static int calls; }
class DoubleRule extends Base { public int apply(int n) { calls++; return n * 2; } }
class Reject extends Base { public int apply(int n) { calls++; throw new IllegalArgumentException(); } }
public class Main {

    public static void main(String[] args) {
        Rule[] rules = {new DoubleRule(), new Reject(), new DoubleRule()};
        int x = 2;
        for (Rule r : rules) {
            try { x = r.apply(x); }
            catch (IllegalArgumentException e) { x += 3; }
            finally { System.out.print(x + " "); }
        }
        System.out.println("| " + Base.calls);
    }
}
정답과 풀이
4 7 14 | 3

2 → 정상4 → 실패하여 catch에서7 → 정상14입니다. 세 메서드 모두 calls를 늘렸으므로3입니다.

제작 P03

도서 대출과 반납 상태

요구사항 · Book의 private borrowed는 처음 false입니다. borrow는 이미 대출 중이면 IllegalStateException, 반납은 false로 바꿉니다. 대출·대출·반납·대출을 실행해 두 번째 대출 실패 후 마지막 대출이 가능하게 만드세요.

설계 순서 · 상태 검사 → 성공 시 변경. 실패 후에도 반납을 실행할 수 있게 대출 시도별로 try-catch.

정답과 풀이
class Book {
    private boolean borrowed;
    void borrow() { if (borrowed) throw new IllegalStateException(); borrowed = true; }
    void back() { borrowed = false; }
    boolean isBorrowed() { return borrowed; }
}
public class Main {

    public static void main(String[] args) {
        Book b = new Book();
        for (String cmd : new String[]{"B", "B", "R", "B"}) {
            try {
                if (cmd.equals("B")) b.borrow(); else b.back();
                System.out.print("OK ");
            } catch (IllegalStateException e) { System.out.print("FAIL "); }
        }
        System.out.println("| " + b.isBorrowed());
    }
}
OK FAIL OK OK | true

실패한 중복 대출은 상태를 바꾸지 않습니다. 추가 검증: B,R이면 최종false입니다.

제작 P04

정상 입력만 쌓는 거래 장부

요구사항 · Account는 초기잔액100, deposit은 양수만 받습니다. 문자열 {"20","x","-5","30"}을 처리하고 정상 입금 횟수와 최종잔액을 출력하세요. 모든 시도는 finally에서 셉니다.

설계 순서 · 문자열 변환 → 메서드 검사 → 성공 횟수 증가 → finally에서 시도 증가.

정답과 풀이
class Account {
    private int balance;
    Account(int n) { balance = n; }
    void deposit(int n) { if (n <= 0) throw new IllegalArgumentException(); balance += n; }
    int get() { return balance; }
}
public class Main {

    public static void main(String[] args) {
        Account a = new Account(100);
        int ok = 0, tries = 0;
        for (String raw : new String[]{"20", "x", "-5", "30"}) {
            try { a.deposit(Integer.parseInt(raw)); ok++; }
            catch (IllegalArgumentException e) { System.out.print("X "); }
            finally { tries++; }
        }
        System.out.println("| " + a.get() + " " + ok + " " + tries);
    }
}
X X | 150 2 4

NumberFormatException은 IllegalArgumentException의 자식입니다. 실패 두 건 모두 잔액과 성공 횟수를 바꾸지 않습니다. 추가 검증: {"0","x"}이면100, 성공0, 시도2입니다.

제작 P05

공통 틀을 둔 작업 파이프라인

요구사항 · 추상 Job의 run은 음수 입력을 거절하고 compute를 호출합니다. AddJob은+3, DoubleJob은×2입니다. 초기4에 AddJob, DoubleJob을 차례로 적용해14를 출력하세요.

설계 순서 · 공통 검사는 부모 run, 실제 계산은 자식 compute. 공통 타입 배열로 순차 실행.

정답과 풀이
abstract class Job {
    final int run(int n) { if (n < 0) throw new IllegalArgumentException(); return compute(n); }
    abstract int compute(int n);
}
class AddJob extends Job { @Override int compute(int n) { return n + 3; } }
class DoubleJob extends Job { @Override int compute(int n) { return n * 2; } }
public class Main {

    public static void main(String[] args) {
        Job[] pipeline = {new AddJob(), new DoubleJob()};
        int x = 4;
        for (Job job : pipeline) x = job.run(x);
        System.out.println(x);
    }
}
14

4→7→14입니다. 추가 검증: 초기−1이면 첫 단계의 공통 검사에서 거절해야 합니다. 호출자에서 잡아 오류 메시지를 출력하도록 확장해 보세요.

제작 P06

객체 참조를 공유하는 장바구니

요구사항 · Product p의 가격은100입니다. 배열 {p,p,new Product(200)}를 만들고 p.price를150으로 바꾼 다음 배열 원소 가격의 합을 출력하세요. 별도 객체 복사본을 쓰는 경우와도 비교하세요.

설계 순서 · new 횟수와 배열 칸의 화살표를 먼저 그리기 → 참조 공유 후 합산.

정답과 풀이
class Product { int price; Product(int n) { price = n; } }
public class Main {

    public static void main(String[] args) {
        Product p = new Product(100);
        Product[] cart = {p, p, new Product(200)};
        p.price = 150;
        int total = 0;
        for (Product item : cart) total += item.price;
        System.out.println(total);
    }
}
500

공유된150이 두 번, 별도의200이 한 번입니다. 추가 검증: 배열을 {new Product(100),new Product(100),new Product(200)}로 만들면 p의 변경과 무관하게400입니다.

제작 P07

상속과 static으로 입장 요금 집계

요구사항 · Visitor의 fee는1000, Child의 fee는600입니다. {일반,아동,아동}을 공통 타입 배열로 처리하고 static total에 합산하세요. 출력은2200입니다.

설계 순서 · 메서드는 오버라이딩, 합계는 클래스 공유값. 지역변수 합계와 혼동하지 않기.

정답과 풀이
class Visitor { static int total; int fee() { return 1000; } }
class Child extends Visitor { @Override int fee() { return 600; } }
public class Main {

    public static void main(String[] args) {
        Visitor[] list = {new Visitor(), new Child(), new Child()};
        for (Visitor v : list) Visitor.total += v.fee();
        System.out.println(Visitor.total);
    }
}
2200

실제 객체에 따라1000+600+600입니다. 추가 검증: 일반 객체 하나를 추가하면3200입니다.

제작 P08

종합 · 실행 전략과 오류 통계

요구사항 · Operation 인터페이스를 구현한 Divide로24/n을 계산하세요. 입력 {"3","0","bad","6"}에서 정상 결과만 합산합니다. static calls는 메서드 호출수, 로컬 errors는 모든 실패수, finally의 finished는 입력 처리수를 셉니다.

설계 순서 · 변환 전에 호출 횟수를 늘리지 않기 → 구현 메서드에서 calls 증가 → 원소별 catch·finally.

정답과 풀이
interface Operation { int apply(int n); }
class Divide implements Operation {
    static int calls;
    public int apply(int n) { calls++; return 24 / n; }
}
public class Main {

    public static void main(String[] args) {
        Operation op = new Divide();
        int sum = 0, errors = 0, finished = 0;
        for (String raw : new String[]{"3", "0", "bad", "6"}) {
            try { sum += op.apply(Integer.parseInt(raw)); }
            catch (NumberFormatException | ArithmeticException e) { errors++; }
            finally { finished++; }
        }
        System.out.println(sum + " " + Divide.calls + " " + errors + " " + finished);
    }
}
12 3 2 4

정상8+4=12, 메서드 호출은3·0·6의3회입니다. bad는 변환 단계에서 실패합니다. 실패2, 전체처리4입니다. 추가 검증: {"bad"}이면0 0 1 1입니다.
