01. 실습 준비 · 이렇게 사용하세요

한 열의 조건은 열 옆에, 여러 열의 조건은 괄호 목록으로 씁니다. 외래키는 테이블 수준으로 통일합니다.

CREATE TABLE tbl_enroll (
    student_id INT,
    course_id INT,
    score INT NOT NULL,
    PRIMARY KEY (student_id, course_id),
    CHECK (score BETWEEN 0 AND 100)
);

CONSTRAINT · 조건에 이름 붙이기

이름을 붙이면 해당 제약조건을 찾거나 삭제하기 쉽습니다.

CREATE TABLE tbl_member (
    id INT PRIMARY KEY,
    email VARCHAR(40),
    score INT,
    CONSTRAINT uq_email UNIQUE (email),
    CONSTRAINT ck_score CHECK (score >= 0)
);

네 가지 함정 · DEFAULT는 명시한 NULL을 대체하지 않습니다. CHECK는 NULL 금지를 대신하지 않습니다. 일반 UNIQUE는 NULL 여러 개를 허용합니다. 복합키는 각 열이 아니라 값의 조합에 조건을 겁니다.

2-3. 외래키와 참조 동작

부모 키는 기본키 또는 적절한 유일 키로 준비합니다. 열 개수·순서를 맞추고 대응 열의 자료형을 맞춥니다. 선택 참조는 자식 NULL 허용, 필수 참조는 NOT NULL. 복합 외래키는 일부 열이 NULL이면 검사를 통과할 수 있으므로 모든 열을 필수로 하려면 각각 NOT NULL을 붙입니다. 생성·입력은 부모부터, 삭제는 자식부터 합니다.

2-4. ALTER TABLE · 공통으로 되는 변경

ALTER TABLE tbl_student ADD COLUMN memo VARCHAR(30);
ALTER TABLE tbl_student DROP COLUMN memo;
ALTER TABLE tbl_student RENAME COLUMN score TO points;
ALTER TABLE tbl_student RENAME TO tbl_learner;

ALTER TABLE tbl_learner ALTER COLUMN points SET DEFAULT 0;
ALTER TABLE tbl_learner ALTER COLUMN points DROP DEFAULT;
ALTER TABLE tbl_learner ADD CONSTRAINT ck_points CHECK (points >= 0);
ALTER TABLE tbl_learner DROP CONSTRAINT ck_points;

ADD CONSTRAINT 이름 PRIMARY KEY / UNIQUE / CHECK / FOREIGN KEY …로 제약조건을 추가합니다. 기존 행이 새 조건을 위반하면 추가할 수 없습니다. SET DEFAULT는 이후 입력의 기본값만 바꿉니다. DROP DEFAULT 뒤 열을 생략했을 때의 처리는 DBMS·모드에 따라 다를 수 있어, 실습에서는 NULL을 명시해 입력합니다.

여기서 DROP CONSTRAINT는 이름을 지정한 CHECK·UNIQUE·FOREIGN KEY에 사용합니다. 기본키 삭제, 자료형 변경, 기존 열의 NOT NULL 설정·해제는 같은 문장으로 통일하기 어려워 생략합니다.

2-5. 복사 · 임시 테이블 · TRUNCATE

조회 결과를 테이블로

AS SELECT는 조회 결과로 새 테이블을 만듭니다. WHERE 1 = 0이면 행 없이 결과 열만 만듭니다.

CREATE TABLE tbl_high AS
SELECT id, score FROM tbl_student
WHERE score >= 70;

CREATE TABLE tbl_empty AS
SELECT id, score FROM tbl_student
WHERE 1 = 0;

임시 객체 · 비우기 · 삭제

임시 테이블은 현재 연결에서 사용합니다. TRUNCATE는 전체 행을 비우고, DROP은 테이블을 없앱니다.

CREATE TEMPORARY TABLE tbl_temp (id INT);
TRUNCATE TABLE tbl_temp;
DROP TABLE tbl_temp;

CREATE TABLE IF NOT EXISTS tbl_note (id INT);
DROP TABLE IF EXISTS tbl_note;

AS SELECT를 제약조건·기본값·인덱스까지 보존하는 완전 복제로 보지 않습니다. TRUNCATE에는 WHERE를 붙이지 않으며, 외래키가 참조 중인 부모 테이블은 비우기에 제한이 있습니다.

2-6. 뷰 · 저장된 조회 정의

CREATE VIEW vw_high (student_id, score) AS
SELECT id, score FROM tbl_student WHERE score >= 70;

CREATE OR REPLACE VIEW vw_high (student_id, score) AS
SELECT id, score FROM tbl_student WHERE score >= 80
WITH CHECK OPTION;

DROP VIEW IF EXISTS vw_high;

AS 뒤에 SELECT. OR REPLACE는 정의 교체. 두 제품에서 교체하려면 기존 열 이름·순서·자료형을 유지하는 형태로 연습합니다. WITH CHECK OPTION은 뷰를 통한 입력·수정이 뷰 조건을 벗어나지 못하게 합니다. 원본을 직접 수정하는 것까지 막지는 않습니다.

CHECK OPTION은 수정 가능한 뷰에 사용합니다. 집계·GROUP BY·DISTINCT 등이 있는 뷰는 보통 수정용으로 쓰지 않습니다. 기본 CASCADED는 아래쪽 뷰 조건까지 검사합니다. LOCAL은 현재 조건을 검사하되 아래쪽 뷰 자체에 CHECK OPTION이 있으면 그 검사도 적용됩니다. 뷰 삭제는 원본 테이블 삭제가 아닙니다.

2-7. 인덱스 · 검색을 돕는 구조

CREATE INDEX idx_score ON tbl_student (score);
CREATE INDEX idx_dept_score ON tbl_student (dept_id, score);
CREATE UNIQUE INDEX idx_email ON tbl_student (email);

순서: CREATE [UNIQUE] INDEX 인덱스명 ON 테이블명 (열 목록). 일반 인덱스는 중복을 허용하고 유일 인덱스는 일반 값의 중복을 막습니다. 검색을 도울 수 있지만 저장 공간과 입력·수정 비용도 늘어납니다.

세 문장은 각각 필요한 열이 있는 테이블을 가정합니다. 조회 정렬은 ORDER BY로 지정합니다. 인덱스 단독 삭제 구문은 DBMS별 차이가 있어 생략합니다.

실습 7: 이름을 붙인 제약조건 추가·삭제

ADD CONSTRAINT는 기존 데이터도 검사한다. 위반 행이 이미 있으면 추가에 실패한다. 기본키 삭제 문법은 공통 예제에서 제외한다.

STEP 1 · 실행

ALTER TABLE tbl_l07 ADD CONSTRAINT pk_l07 PRIMARY KEY (id);
ALTER TABLE tbl_l07 ADD CONSTRAINT uq_l07_email UNIQUE (email);
ALTER TABLE tbl_l07 ADD CONSTRAINT ck_l07_score CHECK (score >= 0);

예상: PK·UNIQUE·CHECK 추가.

STEP 2 · 실패 확인
INSERT INTO tbl_l07 VALUES (1, NULL, -1);

예상: 실패: ck_l07_score 위반.

STEP 3 · 실행
ALTER TABLE tbl_l07 DROP CONSTRAINT ck_l07_score;
INSERT INTO tbl_l07 VALUES (1, NULL, -1);
