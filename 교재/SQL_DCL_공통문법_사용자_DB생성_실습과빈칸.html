1단계 · 관리자 연결에서 DB와 사용자 생성

기존 관리자 계정으로 아래 문장을 한 번씩 실행합니다. 이미 같은 이름의 계정·DB가 있으면 해당 생성문은 건너뜁니다.

CREATE DATABASE db_dcl;
CREATE USER user_a;
CREATE USER user_b;

DB 생성과 사용자 생성은 별개입니다. 사용자를 만들었다고 테이블 조회·수정 권한까지 생기는 것은 아닙니다.

CREATE USER user_a;는 암호를 지정하지 않는 공통 최소 문법입니다. 실행 후 관리 도구에서 user_a·user_b의 로그인 암호를 설정하세요. 암호 지정 SQL과 로그인 정책은 DBMS별로 달라 공통 예제에 섞지 않습니다. 관리자 계정 user_admin은 새로 만드는 계정이 아니라 기존 관리자를 가리키는 이름입니다.

DB 공간과 테이블스페이스 구별

2단계 · DB 선택과 연결 준비

먼저 관리자 연결의 접속 데이터베이스를 db_dcl로 선택하세요. 일반 사용자 연결은 실습 1에서 조회 권한을 부여한 뒤 db_dcl에 접속합니다. 관리자가 권한을 주고, 일반 사용자가 동작을 확인합니다.

연결준비할 상태
관리자 · user_admin실습용 DB db_dcl의 테이블·역할 생성과 권한 부여·회수 가능. 본문에서 관리자로 표시한 SQL 실행. 기존 관리자 계정을 사용해도 됨.
user_a1단계에서 만든 일반 로그인 계정. 로그인 암호 설정 후 접속. 관리자 권한·기존 실습 객체 권한·다른 역할이 없는 상태.
user_buser_a와 같은 조건. 재부여 실습에서 사용.
공통 환경실습 시 세 연결 모두 db_dcl 사용. 일반 사용자 연결은 첫 권한 부여 후 접속. 쿼리 도구의 자동 커밋을 켜고 시작.
PostgreSQL 준비일반 계정의 DB 접속과 실습 스키마 접근을 미리 허용. 본문은 기본 public 스키마 사용을 가정. 역할 role_reader도 이 스키마를 읽을 수 있어야 함.
MariaDB 준비본문의 user_a·user_b는 호스트 부분을 생략한 계정명. 각각 호스트가 %인 계정을 가리킨다. 실제 접속도 그 계정으로 매칭되게 준비.

암호·인증 설정만 DBMS별로 준비합니다. 일반 사용자 연결에서 권한을 검사해야 합니다. 관리자 연결에서는 권한이 없어도 실행될 수 있습니다.

02. 핵심 문법 · 이 순서만 먼저

GRANT 권한→ON 객체→TO 사용자→WITH GRANT OPTION 선택
GRANT SELECT ON tbl_student TO user_a;
REVOKE SELECT ON tbl_student FROM user_a;
권한짧은 뜻기본 예제
SELECT조회GRANT SELECT ON tbl_student TO user_a;
INSERT행 추가GRANT INSERT ON tbl_student TO user_a;
UPDATE값 수정GRANT UPDATE ON tbl_student TO user_a;
DELETE행 삭제GRANT DELETE ON tbl_student TO user_a;
TRIGGER테이블의 트리거 생성에 필요GRANT TRIGGER ON tbl_student TO user_a;
EXECUTE함수·프로시저 실행GRANT EXECUTE ON PROCEDURE proc_ping TO user_a;
ALL [PRIVILEGES]해당 객체의 모든 부여 가능 권한GRANT ALL PRIVILEGES ON tbl_student TO user_a;

여러 권한 · 여러 사용자

권한과 사용자는 각각 쉼표로 나열합니다.

GRANT SELECT, UPDATE ON tbl_student TO user_a, user_b;
REVOKE SELECT, UPDATE ON tbl_student FROM user_a, user_b;

열 단위 권한

열 목록은 권한 바로 뒤 괄호 안에. 공통 실습은 SELECT·INSERT·UPDATE입니다.

GRANT SELECT (id, name), UPDATE (score)
ON tbl_student TO user_a;

조건에 쓰는 열도 조회

WHERE와 계산식에서 읽는 열에도 SELECT 권한이 필요합니다.

GRANT SELECT (id), UPDATE (score) ON tbl_student TO user_a;
-- 이 권한이면 WHERE id = 1로 score를 90으로 수정 가능

재부여 자격

객체 권한을 받은 사람이 다른 사람에게도 줄 수 있게 합니다.

GRANT SELECT ON tbl_student TO user_a
WITH GRANT OPTION;

ALL의 범위

ON 뒤 객체의 모든 부여 가능 권한입니다. 재부여 옵션·계정 전체 권한을 뜻하지 않습니다.

GRANT ALL ON tbl_student TO user_a;
-- WITH GRANT OPTION은 별도로 붙인다

역할 부여 · 회수

역할은 권한 묶음. 역할을 사용자에게 줄 때는 ON이 없습니다.

GRANT role_reader TO user_a;
REVOKE role_reader FROM user_a;

역할의 재부여 자격

객체는 GRANT OPTION, 역할은 ADMIN OPTION입니다.

GRANT role_reader TO user_a WITH ADMIN OPTION;

모든 사용자 · PUBLIC

현재와 미래의 모든 사용자 대상. MariaDB 10.11 이상에서 공통입니다.

GRANT SELECT ON tbl_student TO PUBLIC;
REVOKE SELECT ON tbl_student FROM PUBLIC;

함수·프로시저 실행

실행 권한은 EXECUTE. FUNCTION 또는 PROCEDURE로 구분합니다. 아래 객체는 별도로 준비되어 있다고 가정합니다.

GRANT EXECUTE ON PROCEDURE proc_ping TO user_a;
GRANT EXECUTE ON FUNCTION fn_calc TO user_a;

실행 객체의 준비 조건

함수·프로시저 생성문은 DBMS 차이가 있어 생략합니다. 같은 이름의 오버로드가 없는 객체를 준비하면 아래 권한 SQL은 공통으로 쓸 수 있습니다.

REVOKE EXECUTE ON PROCEDURE proc_ping FROM user_a;
REVOKE EXECUTE ON FUNCTION fn_calc FROM user_a;

회수는 권한의 부정이 아님

회수해도 다른 역할이나 PUBLIC 등의 경로에 같은 권한이 남으면 사용 가능합니다.

REVOKE SELECT ON tbl_student FROM user_a;
-- 다른 경로의 SELECT 권한까지 차단하는 문장은 아니다
열 권한 주의 · 테이블 전체 SELECT가 있으면 일부 열 권한만 회수해도 전체 조회가 가능합니다. 전체 SELECT를 먼저 회수한 뒤 필요한 열만 다시 부여하세요. DELETE(score)처럼 DELETE에 열 목록을 붙이는 문법은 사용하지 않습니다.

위 문법은 암기용 예시이며 한꺼번에 실행하는 스크립트가 아닙니다. 실제 실행 순서는 아래 5개 실습을 따르세요. 문법 근거: PostgreSQL GRANT, MariaDB GRANT.

03. 따라하기 · 5개

준비 SQL 다음에 1 → 5 순서로 실행합니다. 각 실습 끝의 정리 SQL까지 실행하세요. 오류가 예상된 문장은 한 줄씩 따로 실행합니다.

실습 1. 조회 허용 → 실제 확인 → 회수

관리자 

GRANT SELECT ON tbl_student TO user_a;

user_a 성공 · 1 / Min, 2 / Jun

SELECT id, name FROM tbl_student ORDER BY id;

관리자 

REVOKE SELECT ON tbl_student FROM user_a;

user_a 실패 · 다른 경로에 조회 권한이 없으므로 거부

SELECT id, name FROM tbl_student;

실습 2. 읽는 열과 고치는 열을 다르게

관리자 

GRANT SELECT (id, name), UPDATE (score)
ON tbl_student TO user_a;

user_a 성공

SELECT id, name FROM tbl_student ORDER BY id;

user_a 성공 · id는 읽을 수 있고 score는 수정 가능

UPDATE tbl_student SET score = 90 WHERE id = 1;

user_a 실패 · 수정 권한만으로 조회할 수는 없음

SELECT score FROM tbl_student;

user_a 실패 · 계산식에서 읽는 score에 SELECT도 필요

UPDATE tbl_student SET score = score + 5 WHERE id = 1;

관리자 실습 권한과 데이터 정리

REVOKE SELECT (id, name), UPDATE (score)
ON tbl_student FROM user_a;
UPDATE tbl_student SET score = 80 WHERE id = 1;

실습 3. 열을 지정해서 추가하고, 행 단위로 삭제

관리자 

GRANT INSERT (id, name), SELECT (id), DELETE
ON tbl_student TO user_a;

user_a 성공 · score는 기본값 0, memo는 NULL

INSERT INTO tbl_student (id, name) VALUES (3, 'Lee');

관리자 확인 · 3 / Lee / 0 / NULL

SELECT id, name, score, memo FROM tbl_student WHERE id = 3;

user_a 성공 · 조건의 id 조회와 행 삭제 권한이 모두 있음

DELETE FROM tbl_student WHERE id = 3;

관리자 실습 권한 정리

REVOKE INSERT (id, name), SELECT (id), DELETE
ON tbl_student FROM user_a;

실습 4. 재부여는 권한과 옵션이 함께 있어야

관리자 

GRANT SELECT ON tbl_student TO user_a;

user_a 부여되지 않음 · 오류 또는 경고로 보고될 수 있음

GRANT SELECT ON tbl_student TO user_b;

관리자 

GRANT SELECT ON tbl_student TO user_a WITH GRANT OPTION;

user_a 성공

GRANT SELECT ON tbl_student TO user_b;

user_b 성공

SELECT id, name FROM tbl_student ORDER BY id;

user_a 먼저 자신이 user_b에게 재부여한 권한 회수

REVOKE SELECT ON tbl_student FROM user_b;

관리자 그다음 user_a의 조회 권한 회수

REVOKE SELECT ON tbl_student FROM user_a;

재부여한 하위 권한부터 정리합니다. 연쇄 회수와 재부여 옵션만의 회수는 DBMS 차이가 있어 실습하지 않습니다. 마지막 문장은 “조회 권한 회수”만 확인하며, 남은 옵션 상태가 두 DBMS에서 같다고 가정하지 않습니다.

실습 5. 역할로 권한 묶어서 주기

관리자 역할 생성은 한 번만 실행

CREATE ROLE role_reader;
GRANT SELECT ON tbl_student TO role_reader;
GRANT role_reader TO user_a;

user_a 역할을 지정한 뒤 조회 성공. 마지막 줄은 역할 지정 해제

SET ROLE role_reader;
SELECT id, name FROM tbl_student ORDER BY id;
SET ROLE NONE;

관리자 멤버십·권한·역할 순서로 정리

REVOKE role_reader FROM user_a;
REVOKE SELECT ON tbl_student FROM role_reader;
DROP ROLE role_reader;

SET ROLE 전이나 SET ROLE NONE 후의 유효 권한은 자동 상속 방식에 따라 달라질 수 있습니다. 이 실습은 역할을 명시적으로 지정한 구간의 조회만 비교합니다. 역할을 재부여하려면 GRANT role_reader TO user_a WITH ADMIN OPTION; 형태를 씁니다.

04. 사용자·DB 관리 빈칸 6제 · 1~6번

관리자 계정으로 실행합니다. 각 문제에서 만드는 계정·DB는 아직 없고, 삭제 문제의 대상은 이미 있다고 가정합니다.

01DB 공간 생성

테이블들을 담을 실습용 데이터베이스 db_dcl을 만든다.

CREATE (1) __________ db_dcl;
1번 정답 · 완성 SQL

(1) DATABASE

CREATE DATABASE db_dcl;

CREATE DATABASE는 데이터베이스 생성이다. 테이블스페이스 생성문과는 다르다.

02사용자 생성

일반 사용자 user_a를 만든다.

CREATE (1) ______ user_a;
2번 정답 · 완성 SQL

(1) USER

CREATE USER user_a;

CREATE USER는 사용자 계정 생성. 암호를 지정하지 않는 공통 최소 문법이다.

03두 번째 사용자

재부여 실습에 사용할 user_b 계정을 만든다.

(1) ________ USER (2) ________;
3번 정답 · 완성 SQL

(1) CREATE · (2) user_b

CREATE USER user_b;

user_는 이 교재에서 사용자 이름을 구별하는 접두어다.

04계정과 DB 구별

연습용 계정 user_temp와 데이터베이스 db_temp를 차례로 만든다.

CREATE (1) ______ user_temp;
CREATE (2) __________ db_temp;
4번 정답 · 완성 SQL

(1) USER · (2) DATABASE

CREATE USER user_temp;
CREATE DATABASE db_temp;

계정은 USER, 데이터베이스는 DATABASE. 두 명령 모두 관리자 연결에서 실행한다.

05사용자 삭제

소유 객체나 남은 권한이 없는 연습용 계정 user_temp를 삭제한다.

다른 실습에 쓰는 user_a·user_b가 아니라 별도의 user_temp를 삭제한다.

DROP (1) ______ user_temp;
5번 정답 · 완성 SQL

(1) USER

DROP USER user_temp;

DROP USER는 계정 삭제. REVOKE는 권한 회수다.

06빈 연습 DB 삭제

연습이 끝난 빈 데이터베이스 db_temp를 삭제한다.

db_temp의 연결을 모두 닫고 다른 DB에 연결한 관리자 계정으로 실행한다. 본 실습의 db_dcl은 삭제하지 않는다.

DROP (1) __________ db_temp;
6번 정답 · 완성 SQL

(1) DATABASE

DROP DATABASE db_temp;

DROP DATABASE는 데이터베이스 제거. 이 문제에서는 빈 연습용 DB만 대상으로 한다.

05. DCL 빈칸 43제 · 7~49번

문제마다 독립된 상황입니다. 앞 문제의 권한이 다음 문제에 누적되지 않습니다. 테이블·계정·필요한 역할는 이미 준비되어 있다고 가정합니다.

부여·회수는 해당 권한을 관리할 수 있는 계정이 실행합니다. REVOKE 문제는 그 권한이 이미 부여되어 있고 재부여에 따른 종속 권한은 없다고 가정합니다.

07권한 부여

user_a에게 학생 테이블 조회 권한을 준다.

(1) _______ SELECT ON tbl_student TO user_a;
7번 정답 · 완성 SQL

(1) GRANT

GRANT SELECT ON tbl_student TO user_a;

GRANT는 권한 부여.

08조회 권한

행을 읽을 수 있게 한다.

GRANT (1) ________ ON tbl_student TO user_a;
8번 정답 · 완성 SQL

(1) SELECT

GRANT SELECT ON tbl_student TO user_a;

조회에 필요한 권한은 SELECT.

09대상과 수신자

권한 대상과 부여받을 사용자를 연결한다.

GRANT SELECT (1) ______ tbl_student (2) ______ user_a;
9번 정답 · 완성 SQL

(1) ON · (2) TO

GRANT SELECT ON tbl_student TO user_a;

ON 뒤는 객체, TO 뒤는 받는 사용자.

10행 추가

새 행을 추가할 권한만 부여한다.

GRANT (1) ________ ON tbl_student TO user_a;
10번 정답 · 완성 SQL

(1) INSERT

GRANT INSERT ON tbl_student TO user_a;

INSERT는 행 추가.

11행 수정

기존 값을 수정할 권한만 부여한다.

GRANT (1) ________ ON tbl_student TO user_a;
11번 정답 · 완성 SQL

(1) UPDATE

GRANT UPDATE ON tbl_student TO user_a;

UPDATE는 값 수정.

12행 삭제

행 삭제 권한만 부여한다.

GRANT (1) ________ ON tbl_student TO user_a;
12번 정답 · 완성 SQL

(1) DELETE

GRANT DELETE ON tbl_student TO user_a;

DELETE는 행 삭제. DROP은 테이블 제거.

13여러 권한

조회와 수정을 함께 허용한다. 조회 권한부터 쓴다.

GRANT (1) ________, (2) ________ ON tbl_student TO user_a;
13번 정답 · 완성 SQL

(1) SELECT · (2) UPDATE

GRANT SELECT, UPDATE ON tbl_student TO user_a;

권한 사이는 쉼표.

14여러 사용자

user_a와 user_b에게 동시에 조회 권한을 준다.

GRANT SELECT ON tbl_student TO user_a(1) ______ user_b;
14번 정답 · 완성 SQL

(1) ,

GRANT SELECT ON tbl_student TO user_a, user_b;

수신 사용자도 쉼표로 나열한다.

15전체 권한

해당 테이블에서 부여 가능한 모든 권한을 준다.

GRANT (1) ______ PRIVILEGES ON tbl_student TO user_a;
15번 정답 · 완성 SQL

(1) ALL

GRANT ALL PRIVILEGES ON tbl_student TO user_a;

ALL PRIVILEGES는 이 테이블 범위. 재부여 옵션은 별도.

16트리거 생성 권한

이 테이블에 트리거를 만들 때 필요한 권한을 준다.

GRANT (1) _________ ON tbl_student TO user_a;
16번 정답 · 완성 SQL

(1) TRIGGER

GRANT TRIGGER ON tbl_student TO user_a;

TRIGGER는 트리거 생성에 필요한 권한이다. 트리거 정의문 자체는 별도다.

17권한 회수

기존 조회 권한을 회수한다.

(1) ________ SELECT ON tbl_student (2) ______ user_a;
17번 정답 · 완성 SQL

(1) REVOKE · (2) FROM

REVOKE SELECT ON tbl_student FROM user_a;

REVOKE … FROM …은 권한 회수.

18트리거 권한 회수

이 테이블의 기존 트리거 권한을 회수한다.

REVOKE (1) _________ ON tbl_student FROM user_a;
18번 정답 · 완성 SQL

(1) TRIGGER

REVOKE TRIGGER ON tbl_student FROM user_a;

회수할 권한을 REVOKE 다음에 적는다.

19복수 권한 회수

추가와 삭제 권한을 함께 회수한다. 추가 권한부터 쓴다.

REVOKE (1) ________, (2) ________ ON tbl_student FROM user_a;
19번 정답 · 완성 SQL

(1) INSERT · (2) DELETE

REVOKE INSERT, DELETE ON tbl_student FROM user_a;

여러 권한의 회수도 쉼표로 연결한다.

20복수 사용자 회수

두 사용자의 기존 조회 권한을 회수한다.

REVOKE SELECT ON tbl_student (1) ______ user_a, user_b;
20번 정답 · 완성 SQL

(1) FROM

REVOKE SELECT ON tbl_student FROM user_a, user_b;

GRANT는 TO, REVOKE는 FROM.

21전체 권한 회수

이 테이블의 권한을 ALL PRIVILEGES로 회수한다.

REVOKE (1) ________________ ON tbl_student FROM user_a;
21번 정답 · 완성 SQL

(1) ALL PRIVILEGES / ALL

REVOKE ALL PRIVILEGES ON tbl_student FROM user_a;

범위는 ON 뒤의 테이블이다. 계정 삭제 명령이 아니다.

22열 단위 조회

이름과 점수 열만 읽게 한다. 이름을 먼저 쓴다.

GRANT SELECT ((1) ______, (2) _______) ON tbl_student TO user_a;
22번 정답 · 완성 SQL

(1) name · (2) score

GRANT SELECT (name, score) ON tbl_student TO user_a;

열 목록은 권한 바로 뒤 괄호 안에 적는다.

23열 단위 수정

점수 열만 수정하게 한다.

GRANT (1) ________ (score) ON tbl_student TO user_a;
23번 정답 · 완성 SQL

(1) UPDATE

GRANT UPDATE (score) ON tbl_student TO user_a;

UPDATE(score)는 score 열에 대한 수정 권한.

24열 단위 추가

id와 name을 지정하여 행을 추가하게 한다.

GRANT (1) ________ (id, name) ON tbl_student TO user_a;
24번 정답 · 완성 SQL

(1) INSERT

GRANT INSERT (id, name) ON tbl_student TO user_a;

나머지 열에는 기본값 또는 NULL이 들어간다. 제약조건도 만족해야 한다.

25열 단위 회수

기존 score 열 수정 권한을 회수한다.

REVOKE UPDATE ((1) _______) ON tbl_student FROM user_a;
25번 정답 · 완성 SQL

(1) score

REVOKE UPDATE (score) ON tbl_student FROM user_a;

열 단위로 부여한 권한을 같은 형태로 회수한다.

26조회·수정 열 구분

id를 읽고 score를 수정하게 한다.

GRANT (1) ________ (id), (2) ________ (score)
ON tbl_student TO user_a;
26번 정답 · 완성 SQL

(1) SELECT · (2) UPDATE

GRANT SELECT (id), UPDATE (score)
ON tbl_student TO user_a;

WHERE id = 1에 쓰는 id에도 조회 권한이 필요하다.

27조건 열의 권한

score 수정 권한은 이미 있다. WHERE id = 1을 쓸 수 있도록 부족한 권한을 준다.

GRANT (1) ________ ((2) ______) ON tbl_student TO user_a;
27번 정답 · 완성 SQL

(1) SELECT · (2) id

GRANT SELECT (id) ON tbl_student TO user_a;

조건에서 읽는 id에 SELECT 권한이 필요하다.

28계산식의 권한

UPDATE(score)와 SELECT(id)는 이미 있다. score = score + 5에 필요한 권한을 추가한다.

GRANT (1) ________ ((2) _______) ON tbl_student TO user_a;
28번 정답 · 완성 SQL

(1) SELECT · (2) score

GRANT SELECT (score) ON tbl_student TO user_a;

기존 score 값을 읽으므로 SELECT(score)가 필요하다.

29재부여 허용

user_a가 받은 조회 권한을 다른 사용자에게도 줄 수 있게 한다.

GRANT SELECT ON tbl_student TO user_a
WITH (1) _______ (2) ________;
29번 정답 · 완성 SQL

(1) GRANT · (2) OPTION

GRANT SELECT ON tbl_student TO user_a
WITH GRANT OPTION;

WITH GRANT OPTION은 객체 권한을 다시 부여할 수 있게 한다.

30프로시저 실행 권한

미리 준비된 proc_ping 프로시저의 실행을 허용한다.

인자 없는 proc_ping 프로시저가 존재하고, 같은 이름의 오버로드는 없다. 프로시저 생성은 별도 환경 준비다.

GRANT (1) _________ ON PROCEDURE proc_ping TO user_a;
30번 정답 · 완성 SQL

(1) EXECUTE

GRANT EXECUTE ON PROCEDURE proc_ping TO user_a;

프로시저 실행은 EXECUTE 권한이다. ON PROCEDURE로 객체 종류를 적는다.

31받은 권한 전달

user_a가 자신의 조회 권한을 user_b에게 부여한다.

관리자가 user_a에게 SELECT WITH GRANT OPTION을 먼저 부여했다. user_a 연결에서 실행한다.

GRANT (1) ________ ON tbl_student TO (2) ________;
31번 정답 · 완성 SQL

(1) SELECT · (2) user_b

GRANT SELECT ON tbl_student TO user_b;

이 문장의 실행자는 user_a다. user_a는 조회 권한과 재부여 자격을 갖고 있다.

32ALL과 옵션

전체 권한을 주고, 그것을 다시 부여할 자격도 명시한다.

GRANT ALL PRIVILEGES ON tbl_student TO user_a
(1) ___________________;
32번 정답 · 완성 SQL

(1) WITH GRANT OPTION

GRANT ALL PRIVILEGES ON tbl_student TO user_a
WITH GRANT OPTION;

ALL만으로는 재부여 자격까지 포함되지 않는다.

33역할 생성

조회용 역할 role_reader를 만든다.

CREATE (1) ______ role_reader;
33번 정답 · 완성 SQL

(1) ROLE

CREATE ROLE role_reader;

역할은 권한을 묶어서 관리하는 단위다.

34역할에 권한 부여

역할에 테이블 조회 권한을 준다.

GRANT SELECT ON tbl_student TO (1) _____________;
34번 정답 · 완성 SQL

(1) role_reader

GRANT SELECT ON tbl_student TO role_reader;

사용자 대신 역할을 수신자로 쓸 수 있다.

35사용자에게 역할 부여

user_a에게 role_reader 역할을 준다.

GRANT (1) _____________ TO (2) ________;
35번 정답 · 완성 SQL

(1) role_reader · (2) user_a

GRANT role_reader TO user_a;

역할 부여에는 ON 테이블을 쓰지 않는다.

36역할 활성화

user_a가 이미 받은 role_reader 역할을 현재 연결에서 사용한다.

SET (1) ______ role_reader;
36번 정답 · 완성 SQL

(1) ROLE

SET ROLE role_reader;

두 DBMS 모두 SET ROLE을 지원한다. 자동 상속 방식은 다르다.

37역할 지정 해제

현재 연결의 명시적 역할 지정을 해제한다.

SET ROLE (1) ______;
37번 정답 · 완성 SQL

(1) NONE

SET ROLE NONE;

NONE은 역할 지정 해제. 이 명령만으로 모든 권한이 사라진다고 판단하지 않는다.

38역할 회수

user_a에게 부여한 role_reader 역할을 회수한다.

REVOKE (1) _____________ (2) ______ user_a;
38번 정답 · 완성 SQL

(1) role_reader · (2) FROM

REVOKE role_reader FROM user_a;

역할 회수도 ON 없이 REVOKE 역할 FROM 사용자.

39역할 재부여

user_a가 role_reader 역할을 다른 사람에게도 줄 수 있게 한다.

GRANT role_reader TO user_a WITH (1) _______ OPTION;
39번 정답 · 완성 SQL

(1) ADMIN

GRANT role_reader TO user_a WITH ADMIN OPTION;

역할의 재부여는 WITH ADMIN OPTION.

40옵션 구별

객체 권한 재부여와 역할 재부여 옵션을 각각 채운다.

GRANT SELECT ON tbl_student TO user_a WITH (1) _______ OPTION;
GRANT role_reader TO user_a WITH (2) _______ OPTION;
40번 정답 · 완성 SQL

(1) GRANT · (2) ADMIN

GRANT SELECT ON tbl_student TO user_a WITH GRANT OPTION;
GRANT role_reader TO user_a WITH ADMIN OPTION;

객체 권한은 GRANT OPTION, 역할은 ADMIN OPTION.

41역할에서 권한 회수

역할 자체는 남기고, 역할에 준 조회 권한만 회수한다.

REVOKE SELECT ON tbl_student FROM (1) _____________;
41번 정답 · 완성 SQL

(1) role_reader

REVOKE SELECT ON tbl_student FROM role_reader;

역할 멤버십 회수와 역할의 객체 권한 회수는 구별한다.

42빈 역할 삭제

멤버십과 관련 권한을 정리한 role_reader 역할을 삭제한다.

DROP (1) ______ role_reader;
42번 정답 · 완성 SQL

(1) ROLE

DROP ROLE role_reader;

DROP ROLE은 역할 자체를 제거한다. 역할 소유 객체는 없다고 가정한다.

43모든 사용자에게 부여

현재와 이후에 생성될 모든 사용자에게 조회 권한을 준다.

PUBLIC 문제는 MariaDB 10.11 이상을 기준으로 한다.

GRANT SELECT ON tbl_student TO (1) ________;
43번 정답 · 완성 SQL

(1) PUBLIC

GRANT SELECT ON tbl_student TO PUBLIC;

PUBLIC은 모든 사용자를 뜻하는 특별한 대상이다. MariaDB 10.11 이상.

44PUBLIC 권한 회수

모두에게 부여한 조회 권한을 회수한다.

MariaDB 10.11 이상. 다른 경로의 권한은 별개다.

REVOKE SELECT ON tbl_student FROM (1) ________;
44번 정답 · 완성 SQL

(1) PUBLIC

REVOKE SELECT ON tbl_student FROM PUBLIC;

직접 받은 권한이나 다른 역할에서 오는 권한까지 없어지는 것은 아니다.

45프로시저 실행 권한 회수

proc_ping 프로시저의 기존 실행 권한을 회수한다.

30번과 같은 프로시저가 존재하며, 회수할 권한이 이미 부여되어 있다.

REVOKE (1) _________ ON (2) ___________ proc_ping FROM user_a;
45번 정답 · 완성 SQL

(1) EXECUTE · (2) PROCEDURE

REVOKE EXECUTE ON PROCEDURE proc_ping FROM user_a;

프로시저 객체를 명시하여 실행 권한을 회수한다.

46최소 권한

조회와 행 추가만 허용한다. 조회 권한부터 쓴다.

GRANT (1) ________, (2) ________ ON tbl_student TO user_a;
46번 정답 · 완성 SQL

(1) SELECT · (2) INSERT

GRANT SELECT, INSERT ON tbl_student TO user_a;

조회·추가만 요구했다면 ALL은 불필요하다.

47테이블 권한을 열 권한으로 축소

현재 테이블 전체 SELECT만 있다. 먼저 이를 회수하고 name 열만 허용한다.

다른 역할·PUBLIC·열 단위 SELECT는 없다. 재부여한 권한도 없다.

REVOKE (1) ________ ON tbl_student FROM user_a;
GRANT SELECT ((2) ______) ON tbl_student TO user_a;
47번 정답 · 완성 SQL

(1) SELECT · (2) name

REVOKE SELECT ON tbl_student FROM user_a;
GRANT SELECT (name) ON tbl_student TO user_a;

전체 SELECT를 남긴 채 일부 열 권한만 회수해도 전체 조회는 막히지 않는다.

48DELETE 조건에 필요한 권한

id가 3인 행만 삭제하려 한다. DELETE 외에 id를 읽을 권한도 부여한다.

GRANT (1) ________, SELECT ((2) ______) ON tbl_student TO user_a;
48번 정답 · 완성 SQL

(1) DELETE · (2) id

GRANT DELETE, SELECT (id) ON tbl_student TO user_a;

DELETE에는 열 목록을 붙이지 않는다. 조건에서 읽는 열은 SELECT 권한도 필요하다.

49마지막 종합

두 사용자에게 조회·수정 권한과 재부여 자격을 준다.

(1) _______ SELECT, UPDATE (2) ______ tbl_student
(3) ______ user_a, user_b WITH (4) _______ OPTION;
49번 정답 · 완성 SQL

(1) GRANT · (2) ON · (3) TO · (4) GRANT

GRANT SELECT, UPDATE ON tbl_student
TO user_a, user_b WITH GRANT OPTION;

순서: GRANT 권한 ON 객체 TO 수신자 WITH GRANT OPTION.

06. 시험 직전 · 헷갈리는 지점

상황맞는 판단
계정 생성 / DB 공간 생성CREATE USER user_a; / CREATE DATABASE db_dcl;
계정 삭제 / 권한 회수DROP USER / REVOKE. 서로 다른 작업이다.
테이블스페이스CREATE TABLESPACE는 MariaDB에서 지원하지 않아 공통 SQL 실습에서 제외.
권한 부여 / 회수GRANT … TO / REVOKE … FROM
열 목록 위치UPDATE(score) ON 테이블. ON 뒤에 열 목록을 붙이지 않는다.
역할을 사용자에게 부여GRANT 역할 TO 사용자. ON이 없다.
객체 권한 / 역할 재부여WITH GRANT OPTION / WITH ADMIN OPTION
UPDATE(score)만 있음score 조회는 별도 SELECT 필요. WHERE·계산식의 읽기 권한도 확인.
SELECT 전체 + 일부 열 권한 회수전체 SELECT가 남으면 그 열도 계속 읽을 수 있다.
ALL PRIVILEGES이 객체의 부여 가능 권한. 재부여 자격은 별도. DROP 권한이 공통으로 생긴다고 해석하지 않는다.
REVOKE 실행계정 삭제가 아니다. 다른 역할·PUBLIC 등의 동일 권한은 별개다.
공통 실습에서 제외한 항목

연쇄 권한 회수(CASCADE·RESTRICT), 재부여 옵션만의 회수, DBMS별 시스템·스키마·시퀀스 권한은 실행 문법이나 효과가 달라 제외했습니다. REFERENCES는 MariaDB 문서에서 사용되지 않는 권한으로 설명하므로 공통 기능 실습에 넣지 않았습니다.

함수·프로시저·트리거의 생성문은 생략하고, 공통으로 작성 가능한 권한 제어문만 소개했습니다. 이 교재가 정보처리기사 DCL 전체 출제 범위를 보증하는 것은 아닙니다.
